# Telegram Mini App записи на услуги: ТЗ на фронтенд MVP (экраны бизнеса)

> Документ для кодинг-агента. Контракт бэкенда описан в `API.md`, он главнее любых догадок. Рядом лежит папка `design/` с исходниками макетов (`*.dc.html`): это HTML с inline-стилями. Используй их как **эталон вёрстки, отступов, цветов и текстов**. Код из них не копируй: там свой рантайм (`<x-dc>`, `{{holes}}`, `<sc-for>`), а писать нужно на стеке ниже.

## 0. Контекст продукта

Бизнес (мастер маникюра и т. п.) публикует расписание: дни и в каждом дне несколько **окон**. Клиент открывает мини-апп, выбирает свободное окно и записывается. Окно переходит в статус «забронировано, не подтверждено». Бизнес подтверждает запись, окно становится «занято», бот уведомляет клиента. За день до записи и в день записи бот присылает напоминания.

MVP в этом документе: **4 экрана роли «бизнес»** с общим нижним навбаром:
`Календарь` · `Записи` · `Профиль` · `Настройки`.

## 1. Стек

| Слой | Что подключить | Зачем |
|---|---|---|
| Сборка | **Vite** + **React** + **TypeScript** (strict) | Мини-апп — это SPA. SSR не нужен, Next.js избыточен |
| Telegram SDK | **`@tma.js/sdk`** + **`@tma.js/sdk-react`** | `init()`, `initData`, тема, viewport, safe-area, BackButton, haptics. Сверить API с https://docs.telegram-mini-apps.com/packages/tma-js-sdk-react |
| Стили | **Tailwind CSS v4** (`@tailwindcss/vite`) | Токены из раздела 3 оформить через `@theme` |
| Роутинг | **React Router** (data/declarative mode) или **TanStack Router** | 4 вкладки = 4 маршрута, у каждого свой deep link |
| Серверные данные | **TanStack Query** | Кэш, мутации confirm/reject, оптимистичные апдейты |
| Клиентский стейт | **Zustand** (по необходимости) | Выбранная дата, UI-флаги |
| Валидация | **zod** | Схемы ответов API и форм |
| Даты | **date-fns** + локаль `ru`, **@date-fns/tz** | Неделя с понедельника, формат «Ср, 11 нояб», расчёты в часовом поясе продавца |
| Иконки | **lucide-react** | Стиль совпадает с макетом (stroke 2, 24px) |
| Моки API | **MSW** | Фронт пишется до готовности бэкенда |
| Качество | ESLint + Prettier, **Vitest** + Testing Library | |
| Локальная отладка | `@tma.js/sdk` mockTelegramEnv (только в dev) + туннель (cloudflared/ngrok) для теста в реальном Telegram | |

Пакетный менеджер: pnpm. Версии ставить последние стабильные (`pnpm add <pkg>`), не выдумывать.

## 3. Дизайн-токены (из макетов)

Цвета:
- `bg` #F2F3F7 — фон экрана; `surface` #FFFFFF — карточки; `surface-muted` #F6F7FA
- `text` #15171C; `text-muted` #5F6573; `text-subtle` #3A3F4A
- `border` #E1E4EB; `divider` #EEF0F4; `tabbar-border` #E4E6EC
- `accent` #2A6BE0 (hover #1F55B8); `accent-soft` = accent с альфой ~12% (`#2A6BE01F`)
- Статус **Занято**: текст #1F4FB5, фон #E3ECFC, полоса слева = accent
- Статус **Ждёт подтверждения**: текст #8A4300, фон #FFF0DB, обводка карточки #F2B66B
- Статус **Свободно**: пунктирная полоса #C9CDD6, текст #3A3F4A
- Бейдж-счётчик в навбаре: #D9480F, текст белый

Акцент должен браться из темы Telegram (`themeParams.button_color`) с фолбэком на #2A6BE0. Вынести в CSS-переменную `--accent`. Остальные цвета на MVP фиксированные, светлая тема. Тёмная тема — отдельная задача после MVP.

Типографика: Inter (400/500/600/700) для текста, Manrope (700/800) для заголовков H1 (26px, 800, letter-spacing −0.02em). Размеры: 17px — H2, 15px — основной текст, 13px — вторичный, 11–12px — бейджи и подписи.

Геометрия: базовая ширина 390px, горизонтальный паддинг экрана 16px, вертикальный gap между блоками 16px. Радиусы: карточки 18px, крупные секции 20px, кнопки 12px, бейджи pill (999px). Таргеты нажатия не меньше 44px. Таб-бар 84px с учётом safe-area: `padding-bottom: max(22px, var(--tg-safe-area-inset-bottom))`.

## 4. Экраны

### Общий layout
Контент скроллится, таб-бар закреплён снизу (`position: fixed`). У активной вкладки цвет accent, иконка на pill-подложке `accent-soft` 56×30, подпись 11px/600. Неактивные вкладки — `text-muted`, 500. На вкладке «Записи» бейдж с числом заявок в статусе pending. Иконки lucide: `CalendarDays`, `ClipboardList`, `UserRound`, `SlidersHorizontal`.

### 4.1 Календарь `/calendar` (макет `Main.dc.html`)
- Шапка: подпись месяца («Ноябрь 2026»), H1 «Расписание», кнопки ← → для переключения недели (44×44, белые, бордер).
- WeekStrip: белая карточка, сетка из 7 колонок Пн–Вс. В ячейке день недели, число и до 3 точек-индикаторов окон: accent = занято, оранжевая #E07A10 = ждёт, серая = свободно. Выбранный день залит accent, текст белый. Сб и Вс приглушены.
- Заголовок дня «Среда, 11 ноября» и сводка «N окон · M ждёт».
- Список SlotCard, отсортированный по времени. Слева колонка «начало/конец». Варианты:
  - `confirmed`: бейдж «Занято», `customer.name`, `product.name`;
  - `need_confirmation`: бейдж «Ждёт подтверждения», имя, услуга, `@username`, кнопки «Отклонить» / «Подтвердить»;
  - `free`: «Свободно / Открыто для записи», кнопка ⋯ (меню: изменить время, удалить).
- Кнопка с пунктирной рамкой «+ Добавить окно» открывает bottom sheet: время начала и конца, на выходе `timing` вида `HH:mm-HH:mm`. Ответ `409 slot_conflict` показывать как «Время пересекается с другим окном».

### 4.2 Записи `/bookings` (макет `Bookings.dc.html`)
- H1 «Записи», сегмент-контрол: «Ожидают · N» / «Подтверждены» / «Прошедшие». Вкладку хранить в `?tab=`.
- Ожидают: подсказка «Клиент получит уведомление в Telegram сразу после подтверждения», карточки заявок (аватар с инициалами, имя, @username, бейдж «Ждёт», серый блок «Дата и время / Услуга», кнопки «Отклонить» / «Подтвердить»).
- Подтверждены: строки (день и время, имя, услуга, колокольчик с датой напоминания). Дату напоминания считать на фронте из `date` и `settings.customerNotification`.
- Прошедшие: те же строки, полоса и время приглушены.
- «Отклонить» спрашивает подтверждение через `popup` Telegram. После confirm/reject — haptic feedback и оптимистичное удаление карточки из списка.

### 4.3 Профиль `/profile` (макет `Profile.dc.html`)
- H1 «Профиль» и кнопка «Изменить» (переход в форму, на MVP можно отдельным экраном `/profile/edit`).
- Карточка бизнеса: квадратный аватар 80px (радиус 26, accent, первая буква `title`), `title`, `address` с иконкой MapPin.
- Блок «Ссылка для записи» на фоне accent-soft. Ссылка = `publicLink` из API, кнопки «Копировать» (clipboard и toast) и «Поделиться» (`shareURL` / `openTelegramLink` из SDK).
- «Услуги»: список (название, длительность, цена, шеврон) и кнопка «+ Добавить».
- «О студии»: текстовый блок, `description`.

### 4.4 Настройки `/settings` (макет `Settings.dc.html`)
Группы с uppercase-заголовками 12px. Строка 52px: label, hint и справа либо значение с шевроном, либо Switch 52×32.
- Расписание: рабочие дни, часы работы, перерыв между окнами, горизонт записи.
- Подтверждение записи: автоподтверждение (switch), срок на подтверждение.
- Напоминания клиенту: запись подтверждена, за день до записи, в день записи (switch).
- Уведомления мне: новая заявка (switch).
- Аккаунт: язык, поддержка. (Приложение бесплатное — тарифов и оплаты нет.)
Switch реализовать как `<button role="switch" aria-checked>`. Изменения сохранять сразу через PATCH с оптимистичным апдейтом.

## 5. API

**Источник правды — `API.md`** (рядом с этим файлом). Типы, zod-схемы и MSW-хендлеры строятся строго по нему. Если чего-то не хватает, не додумывай: оставь `TODO(spec)` и сообщи.

Авторизация: в каждом запросе заголовок `Authorization: tma <initDataRaw>`. Значение брать из `@tma.js/sdk`, в http-клиенте добавлять одним interceptor-ом.

Какой эндпоинт обслуживает какой экран:

| Экран / действие | Эндпоинт |
|---|---|
| Календарь: окна недели | `GET /api/slots?periodFrom&periodTo` (диапазон = видимая неделя) |
| Календарь: «+ Добавить окно» | `POST /api/slots` |
| Календарь: ⋯ → изменить / удалить свободное окно | `PATCH /api/slots/{id}`, `DELETE /api/slots/{id}` |
| Записи: «Ожидают» | `GET /api/slots/merchant?status=need_confirmation` |
| Записи: «Подтверждены» | `GET /api/slots/merchant?status=confirmed&periodFrom=<сегодня>` |
| Записи: «Прошедшие» | `GET /api/slots/merchant?status=confirmed&periodTo=<вчера>&order=desc` |
| Подтвердить / Отклонить (Календарь и Записи) | `POST /api/slots/{id}/confirm`, `POST /api/slots/{id}/reject` |
| Бейдж навбара, «Ожидают · N» | `GET /api/slots/merchant/counters` |
| Профиль: карточка, ссылка, «О студии» | `GET /api/merchant/self` |
| Профиль: «Изменить» | `PATCH /api/merchant/self` |
| Профиль: услуги | `GET/POST /api/products`, `PATCH/DELETE /api/products/{id}` |
| Настройки | `GET /api/merchant/settings`, `PATCH /api/merchant/settings` |

Как статусы API ложатся на UI: `free` → «Свободно», `need_confirmation` → «Ждёт подтверждения», `confirmed` → «Занято». `timing` (`"10:00-11:30"`) разбирать в `{ start, end }` в одном хелпере `parseTiming` и покрыть его тестом.

Query keys (TanStack Query): `['slots', periodFrom, periodTo]`, `['merchantSlots', status, params]`, `['counters']`, `['merchant']`, `['settings']`, `['products']`. После confirm/reject/create/delete инвалидировать `slots`, `merchantSlots` и `counters`.

Приложение бесплатное: тарифов, оплаты и платных ограничений нет нигде. «Поддержка» в настройках — статичная ссылка через `openTelegramLink`. Подзаголовок под названием в профиле не выводить: в `Merchant` есть только `title`, `address` и `description` (последний идёт в блок «О студии»).

## 6. Роадмап MVP (задачи по порядку)

Каждая задача — отдельный PR с критериями приёмки.

**Этап 1. Фундамент**
1. Инициализировать Vite + React + TS, ESLint/Prettier, алиас `@/`, структуру папок из раздела 2. *Готово:* `pnpm dev` и `pnpm build` проходят.
2. Подключить Tailwind v4 и токены из раздела 3 (`@theme`, CSS-переменные), шрифты Inter и Manrope. *Готово:* тестовая страница со всеми цветами и шрифтами.
3. Telegram SDK: `init()`, `miniApp.ready()`, `viewport.expand()`, safe-area-переменные, синхронизация `--accent` с темой. Добавить mockTelegramEnv для запуска в браузере. *Готово:* приложение открывается и в браузере, и в Telegram через туннель.
4. Провайдеры: QueryClient, Router с 4 маршрутами, редирект `/` → `/calendar`.
4a. API-слой по `API.md`: http-клиент с `Authorization: tma …` и разбором ошибок `{ error: { code, message } }`, zod-схемы Merchant / Settings / Product / Slot, хелпер `parseTiming`, query keys. MSW-хендлеры на **все** эндпоинты из `API.md` с фикстурами из макетов и правилами статусов (409 на недопустимые переходы). *Готово:* каждый эндпоинт отвечает из мока, схемы проходят тесты.

**Этап 2. UI-кит (`shared/ui`)**
5. Button (primary / secondary / dashed / ghost-icon), Badge (booked / pending / neutral), Card, Avatar (инициалы), ListRow, Switch, SegmentedControl, BottomSheet, Toast. *Готово:* компоненты совпадают с макетами, у всех таргет ≥44px и есть a11y-атрибуты.
6. TabBar: 4 вкладки, активное состояние, бейдж-счётчик, safe-area. Подключить в корневой layout.

**Этап 3. Экраны**
7. Календарь: WeekStrip (навигация по неделям, выбор дня, точки-индикаторы), заголовок дня и сводка, список SlotCard в трёх вариантах.
8. Календарь: добавление окна и изменение даты и времени свободного окна (одна и та же BottomSheet-форма), меню ⋯ у свободного окна (изменить / удалить). Правила — в разделе 7 (п. 3–5). Мутации с инвалидацией запросов.
9. Записи: сегмент-контрол с `?tab=`, три списка, пустые состояния.
10. Confirm/Reject (`POST /api/slots/{id}/confirm|reject`): Telegram-popup с необязательной причиной на отклонение, haptics, оптимистичный апдейт, инвалидация `slots`, `merchantSlots` и `counters` (бейдж в TabBar и точки в календаре).
11. Профиль (`GET /api/merchant/self`, `GET /api/products`): карточка, `publicLink` (копировать и поделиться), список услуг, «О студии».
12. Профиль: форма `PATCH /api/merchant/self` и CRUD услуг через `/api/products` (BottomSheet). Включить BackButton Telegram на вложенных экранах.
13. Настройки (`GET/PATCH /api/merchant/settings`): группы и строки, свитчи с частичным PATCH, экраны выбора значений (рабочие дни, часы, перерыв, горизонт, срок подтверждения, время напоминаний).

**Этап 4. Доводка**
14. Состояния загрузки (скелетоны), ошибок и пустых списков на всех экранах.
15. Тесты: юнит-тесты форматтеров дат и статусов, компонентные тесты SlotCard, BookingRequestCard и TabBar.
16. Сверка с макетами на ширине 360/390/430, проверка в Telegram на iOS и Android. Сборка и деплой статики (Vercel / Cloudflare Pages), URL прописать боту в BotFather.

**Вне MVP (следующие итерации):** экраны клиента (выбор окна, запись, мои записи), тёмная тема, бот-уведомления (бэкенд), выбор роли по `startapp`.

## 7. Уточнения и правила (ответы на вопросы по ТЗ)

Раздел обязателен наравне с остальными. Тексты в кавычках «…» — дословные строки интерфейса.

### 7.1 Часовой пояс
Пояс продавца приходит в `GET /api/merchant/settings` → `timezone` (IANA, например `Asia/Yekaterinburg`). «Сегодня», «вчера», прошлое время и напоминания считаются в этом поясе через `@date-fns/tz`. Пока настройки не загрузились, экраны со слотами показывают скелетон.

### 7.2 Валидация (одинаково в формах, zod и MSW)
| Поле | Правило |
|---|---|
| `merchant.title` | обязательно, 1–64 символа после trim |
| `merchant.address` | необязательно, до 200 |
| `merchant.description` | необязательно, до 1000 |
| `product.name` | обязательно, 1–64 |
| `product.durationMinutes` | 15–480, шаг 15 |
| `product.price` | целое 0–1 000 000 или `null` (пустое поле = `null`) |
| `schedule.workDays` | минимум 1 день |
| `schedule.workHours` | шаг 30 мин, `from` < `to` |
| `schedule.breakMinutes` | одно из 0, 5, 10, 15, 20, 30, 45, 60 |
| `schedule.bookingHorizonDays` | одно из 7, 14, 30, 60 |
| `slotConfirmation.deadlineHours` | одно из 1, 2, 4, 12, 24, 48 |
| `customerNotification.dayBefore.time` | целый час с 08:00 по 22:00 |
| `customerNotification.sameDay.hoursBefore` | одно из 1, 2, 3, 4 |

Ошибка поля выводится под полем красным #C62828, 13px: «Заполните поле», «Слишком длинно», «Недопустимое значение».

### 7.3 Ограничения окон
- Шаг времени 15 мин, длительность от 15 мин, начало и конец в одних сутках (через полночь нельзя).
- Окно в прошлом создать или перенести нельзя: «Нельзя создать окно в прошлом».
- Рабочие часы и дни, перерыв и горизонт для окон, созданных вручную, НЕ проверяются. Это ручное управление.
- Соседние окна с общей границей (10:00–11:00 и 11:00–12:00) пересечением НЕ считаются.

### 7.4 Форма окна (BottomSheet)
Заголовок «Новое окно» или «Изменить окно». Поля «Дата» (`<input type="date">`), «Начало» и «Конец» (`<input type="time" step="900">`). Кнопка на всю ширину «Сохранить». При создании дата по умолчанию — выбранный день. Менять можно и дату, и время.

### 7.5 Меню ⋯ и подтверждения — через Telegram `popup`
Своё меню не рисовать.
- ⋯ у свободного окна: popup без заголовка, кнопки «Изменить время», «Удалить» (destructive), «Отмена».
- Удаление: заголовок «Удалить окно?», текст «{Ср, 11 нояб} · {10:00–11:30}», кнопки «Удалить» (destructive), «Отмена».
- Отклонение (из «Календаря» и из «Записей» одинаково): заголовок «Отклонить запись?», текст «{Имя}, {Ср, 11 нояб} · {12:00–13:30}. Окно снова станет свободным.», кнопки «Отклонить» (destructive), «Отмена». Причину в MVP НЕ вводим, `reason` не отправляем.
- Подтверждение — без popup, сразу мутация и haptic `notificationOccurred('success')`.
- Удаление услуги: заголовок «Удалить услугу?», текст «Существующие записи сохранятся.», кнопки «Удалить» (destructive), «Отмена».

### 7.6 Формы профиля и услуг
Общий вид полей во всех формах: подпись 13px `text-muted` над полем, поле высотой 48px, белое, бордер #E1E4EB, радиус 12, паддинг 0 14px, текст 15px; textarea — 4 строки. Primary-кнопка на всю ширину внизу. Обёртка — BottomSheet: белый, верхние радиусы 20, паддинг 16, «ручка» 36×4 #C9CDD6 сверху, затемнение фона rgba(20,23,28,0.4).
- Профиль: заголовок «Профиль студии», поля «Название», «Адрес», «О студии», кнопка «Сохранить».
- Услуга: заголовок «Новая услуга» или «Изменить услугу», поля «Название», «Длительность» (select 15…480 мин, подписи «30 мин», «1 ч 30 мин»), «Цена, ₽» (placeholder «Не указана»), кнопка «Сохранить». В режиме изменения под ней текстовая кнопка красным «Удалить услугу».

### 7.7 Экраны выбора в настройках
Тап по строке со значением открывает BottomSheet с заголовком = label строки и списком вариантов. Строка варианта 52px, выбранный вариант отмечен иконкой `Check` цвета accent; выбор сразу сохраняется (PATCH) и закрывает шит.
- «Рабочие дни»: 7 чипов-переключателей Пн…Вс (44×44, выбранный залит accent) и кнопка «Сохранить».
- «Часы работы»: два `<input type="time" step="1800">`, «С» и «До», кнопка «Сохранить».
- Время напоминаний: когда свитч «За день до записи» включён, под ним появляется строка «Время отправки» со значением (например «18:00») и шевроном. Когда включён «В день записи» — строка «За сколько» («За 2 часа»). Hint под свитчами («В 18:00», «За 2 часа») берётся из этих значений.
- Строковые значения: часы — «18:00»; минуты — «15 мин»; дни горизонта — «на 1 неделю» / «на 2 недели» / «на 30 дней» / «на 60 дней»; дедлайн — «1 ч», «2 ч», «4 ч», «12 ч», «24 ч», «48 ч».

### 7.8 Язык и поддержка
«Язык» — информационная строка: значение «Русский», без шеврона, не нажимается. «Поддержка» открывает `openTelegramLink(import.meta.env.VITE_SUPPORT_URL)`. Если переменная пустая, строку скрыть. Добавить `VITE_SUPPORT_URL=` в `.env.example`.

### 7.9 Напоминание у подтверждённой записи
Среди включённых напоминаний (`dayBefore`, `sameDay`) берётся ближайшее, которое ещё в будущем. Текст: «Сегодня 18:00», «Завтра 18:00», иначе «{Пт} 18:00». Если ни одного будущего нет — колокольчик и текст скрыть.

### 7.10 Подсказка во вкладке «Ожидают»
При `customerNotification.onConfirm = true` текст «Клиент получит уведомление в Telegram сразу после подтверждения.», при `false` — «Уведомление о подтверждении выключено в настройках.»

### 7.11 Ошибки (серверный `error.message` пользователю не показывать)
| Ситуация | Что показать |
|---|---|
| 401 | Экран на весь контент: «Откройте приложение из Telegram» |
| Ошибка загрузки экрана (сеть, 5xx) | Блок вместо контента: «Не удалось загрузить данные» и кнопка «Повторить» |
| Ошибка мутации (сеть, 5xx) | Toast «Что-то пошло не так. Попробуйте ещё раз», откат оптимистичного апдейта |
| 409 при создании или изменении окна | Под формой: «Время пересекается с другим окном» |
| 409 при confirm, reject или удалении | Toast «Запись уже изменилась, список обновлён» и refetch |
| 404 при мутации окна или услуги (изменение, удаление, confirm, reject) | Закрыть открытую форму или шит, toast «Уже удалено, список обновлён», инвалидировать запросы этой сущности (`slots`, `merchantSlots`, `counters` или `products`) |
| 404 при загрузке экрана (GET) | Как ошибка загрузки экрана: «Не удалось загрузить данные» и «Повторить» |
| 400 | Подсветить поля по правилам 7.2; если не удалось сопоставить — toast «Проверьте введённые данные» |

### 7.12 Toast, загрузка, пустые состояния
- Toast: тёмная плашка #15171C, белый текст 14px, радиус 12, по центру над таб-баром (отступ 12px), автоскрытие через 2,5 с. Тексты: «Окно добавлено», «Окно изменено», «Окно удалено», «Запись подтверждена», «Запись отклонена», «Сохранено», «Ссылка скопирована».
- Загрузка: скелетоны той же формы и размера, что и реальные карточки, цвет #E6E8EE, пульсация opacity 1→0,5.
- Пустые состояния (13px `text-muted`, по центру, отступ 32px сверху):
  - день календаря — «В этот день окон нет» (кнопка «Добавить окно» остаётся);
  - «Ожидают» — «Новых заявок нет»;
  - «Подтверждены» — «Предстоящих записей нет»;
  - «Прошедшие» — «Прошедших записей пока нет»;
  - услуги — «Добавьте первую услугу».

### 7.13 Актуальность данных
TanStack Query: `refetchOnWindowFocus: true`, плюс refetch активных запросов по событию Telegram `activated`. `counters` и `merchantSlots(need_confirmation)` дополнительно опрашиваются раз в 60 с, пока приложение видно. Других механизмов (WebSocket, push) не делать.

### 7.14 Поведение календаря
- При открытии выбран сегодняшний день. При переключении недели выбирается сегодня, если оно в этой неделе, иначе понедельник.
- Месяц в шапке — месяц выбранного дня, «Ноябрь 2026» (именительный падеж, с заглавной).
- Точки под днём: максимум 3, по одной на слот. Порядок заполнения: сначала `need_confirmation`, потом `confirmed`, потом `free`, внутри группы — по времени.
- Сводка дня: «{N} окон · {M} ждёт», склонение через `Intl.PluralRules('ru')` («1 окно», «2 окна», «5 окон»). Если M = 0, часть « · M ждёт» не выводить.

### 7.15 Пустые значения и форматирование
- Цена: `Intl.NumberFormat('ru-RU')` и « ₽» → «1 500 ₽»; `null` → «—».
- Длительность: «30 мин», «1 ч», «1 ч 30 мин».
- Пустой `address` — строку с MapPin скрыть. Пустой `description` — в «О студии» серый текст «Расскажите клиентам о себе», по тапу открывается форма профиля.
- Нет `username` — «@…» не выводить.
- PATCH услуги, окна, профиля и настроек — только изменённые поля.

### 7.16 Геометрия и приёмка
- Визуальные размеры как в макетах, а область нажатия у всего интерактивного не меньше 44×44 (через паддинг или `::before`). Это касается кнопок 36/40px и Switch 32px.
- Таб-бар: высота = 62px + `max(22px, safe-area-inset-bottom)`, контенту снизу такой же отступ.
- Критерий «Готово» для КАЖДОЙ задачи, где он не указан отдельно: lint, typecheck, test и build зелёные; экран совпадает с макетом на ширине 390; описанное поведение и тексты из разделов 4 и 7 реализованы; новых `TODO(spec)` нет или они перечислены в отчёте.
- Пока тестов нет, `test` запускается как `vitest run --passWithNoTests`.
